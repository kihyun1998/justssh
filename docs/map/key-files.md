# Key files

How `justssh-keys` (`crates/justssh-keys/src/`) reads and writes private key files, and what to watch when changing it.

## OpenSSH keys are read as x/crypto/ssh reads them

An OpenSSH private key file (`PROTOCOL.key`) is read with the limits of x/crypto/ssh's `parseOpenSSHPrivateKey` (`keys.go`), since acwbroker reads its host key files and upstream keys with it: one key per file, the bcrypt KDF with at most 2048 rounds (`maxRounds`), and AES-256 in CTR or CBC mode. Other ciphers, such as `aes256-gcm@openssh.com` and `chacha20-poly1305@openssh.com` that `ssh-keygen -Z` can choose, are refused by name before anything is derived; Go cannot read them either. RSA keys are held to Go's bounds: a modulus of at most 16384 bits, primes of at most 8192, an exponent that is odd, at least 3 and at most 24 bits; a private exponent longer than the modulus is refused before any arithmetic, which bounds the work a hostile file can cause and changes no outcome, so no test sees it. Bytes after the private section are ignored, as Go's `Rest` field takes them, and the armor must start a line, as Go's `pem.Decode` wants. An empty passphrase counts as none, as acwbroker passes one only when it is set, and a passphrase given for a key that is not encrypted is refused, as Go's `ParsePrivateKeyWithPassphrase` refuses it.

Two things Go reads are refused here. The file's public halves must match its private key, the outer public key and, for ed25519, the public key stored after the seed, where Go compares the public point only for ECDSA; `ssh-keygen` never writes halves that disagree. And an RSA key under 1024 bits is refused, as the core refuses it (`PrivateKey::rsa`).

2048 rounds of bcrypt-pbkdf take seconds, and many times that unoptimised, so `bcrypt-pbkdf` and `blowfish` are built optimised in dev builds (workspace `Cargo.toml`); the test that reads a key at the round limit took 65 s without and 18 s with (measured on #21).

## Keys are written as acwbroker writes its host key

`KeyFile::to_openssh` writes an unencrypted file of the same structure as x/crypto/ssh's `MarshalPrivateKey`, which is how acwbroker writes `hostkey` and `hostkey-rsa` (`internal/infrastructure/hostkey/file_store.go`), so a Rust broker and a Go one can take each other's files. The check numbers are random and the lines 70 columns wide, as `ssh-keygen` writes them, where Go's `pem.EncodeToMemory` writes 64, so the bytes differ from Go's. The buffers this crate holds key material in zeroize on drop, and the one the file is assembled in zeroizes each allocation it outgrows; `bcrypt-pbkdf` and `cbc` are built with their `zeroize` features. What the RSA arithmetic leaves is not reached: rsa 0.9 and the inverse taken for the CRT coefficient make big integer temporaries that are not wiped, as the core's RSA signing does. The coefficient is taken from the primes alone, not by building a second key.

Generating a host key and publishing it exclusively, as acwbroker's `FileStore.generate` does, is the consumer's: the maintainer chose on #21 to keep the library to reading and writing. Writing an encrypted file is not done.

## Certificates come as an authorized_keys line

`certificate_from_line` reads a certificate as acwbroker does, with x/crypto/ssh's `ParseAuthorizedKey` (`internal/infrastructure/upstream/ssh_dialer.go`): the first line holding a key, past blank and `#` lines, its type taken first as the line's first field and otherwise after an options field, which runs to the first space or tab outside double quotes; the declared type must be the blob's, and the blob must be a certificate, which acwbroker requires next. White space is trimmed as Go's `bytes.TrimSpace` trims it, Unicode spaces included, and the base64 is decoded as Go's `StdEncoding` decodes it, taking unused bits in the last character. A line that does not parse is passed over for the next, as Go passes it over. Two cases differ from Go, both needing more than one line, where acwbroker passes one: the certificate's fields are checked when the key is put under it (`PrivateKey::with_certificate`, `user-authentication.md`), so a broken certificate on an earlier line fails there rather than giving way to a later one; and a plain key's line ends the search with `UnsupportedKeyType` without its key being checked, where Go would pass over a plain key that does not parse. `go_reads_each_certificate_line_as_justssh_keys_does` gives Go and this crate the same 16 lines and compares what each reads, including a certificate line commented out, which both refuse (#47).

## PPK files are read as acwbroker reads them

`KeyFile::from_ppk` reads PuTTY's format as acwbroker's own reader does (`internal/infrastructure/ppk/ppk.go`), since x/crypto/ssh has none: the file as bytes, so a comment in a Windows code page such as CP949 is kept as it is, versions 2 and 3, the headers in the order PuTTY writes them (`sshpubk.c` `ppk_load_s`), RSA, ECDSA and Ed25519 keys, no encryption or AES-256-CBC, and the MAC over the headers and both blobs checked before the key is built. Version 2 derives its keys with SHA-1 and MACs with HMAC-SHA-1; version 3 derives them with Argon2id or Argon2i and MACs with HMAC-SHA-256. Argon2d is refused by name, as acwbroker refuses it because Go's `argon2` has none, although the `argon2` crate here has it; the maintainer chose on #46 to keep acwbroker's behaviour over taking files the Go broker cannot open. It is refused where acwbroker refuses it, after the check for a passphrase, so an Argon2d file given none needs a passphrase first; so is a `Key-Derivation` that names no Argon2 flavour, as `Malformed`. The maintainer chose on #61 to move both there, Argon2d first and the unknown name when a completeness pass found it left behind. The Argon2 settings are outside the MAC and must be used before the MAC can be checked, so a file asking for more than 1 GiB of memory or more than 4 Mi KiB-passes is refused before anything is derived (`KdfTooCostly`), acwbroker's limits. A passphrase given for a file that is not encrypted is not used, as acwbroker ignores it, where an OpenSSH file refuses one. The format cannot tell a wrong passphrase from a damaged encrypted file; both read as `WrongPassphrase`. A file that is not encrypted and fails its MAC reads as `MacMismatch` rather than `Malformed`, so that the broker can name it as acwbroker's `classify` names `ErrMACMismatch`, a wrong passphrase when one was given; the maintainer chose on #61 to add it to the library over leaving the difference. An error names an algorithm, cipher or derivation only when it looks like one, since a file whose line breaks were lost carries its private lines where the algorithm should be. An Argon2 memory below eight blocks a lane is raised to that, as Go's `argon2` raises it. Some files acwbroker reads are refused here, none of which PuTTY or WinSCP writes: a salt under 8 bytes, which the `argon2` crate refuses; a public blob not in canonical form, since the key built from the file must give back the blob the MAC covers; an RSA key under 1024 bits, which the core refuses and Go could not sign with; an ECDSA scalar under 24 bytes, which the `p256` family refuses. An RSA exponent from 2^31 up to the `rsa` crate's limit is read here where acwbroker refuses it. The text is not copied to change its line ends, and the base64 blocks are gathered into a buffer sized once, so no unwiped copy of the private lines is left behind (#46).

The fixtures in `crates/justssh-keys/tests/ppk/` are acwbroker's: PPK v3 files WinSCP 6.5.6 made from `ssh-keygen` keys kept beside them, and one RSA key PuTTYgen saved as v2 and v3 (`README.md` there). WinSCP writes only Argon2id, so Argon2i is checked against vectors from a second implementation (acra_client's pointycastle `PpkKdf`). Against a real peer, sshd accepts all eight WinSCP keys read from their PPK files, its `authorized_keys` taking the public keys of the OpenSSH files they were made from (`sshd.rs`). Argon2 runs optimised in dev builds too (workspace `Cargo.toml`): the PPK tests took 48 s without and 1.5 s with (measured on #46).

## PEM keys are read as x/crypto/ssh reads them

`KeyFile::from_pem` reads what x/crypto/ssh's `ParseRawPrivateKey` and `ParseRawPrivateKeyWithPassphrase` read (`keys.go`), which acwbroker uses for any key that is not PPK: the first PEM block as Go's `pem.Decode` finds it (the first END line, the last BEGIN at the start of a line before it, headers up to the first line without a colon, an END naming the same type), holding PKCS#1 `RSA PRIVATE KEY`, PKCS#8 `PRIVATE KEY` (RSA, ECDSA or Ed25519) or SEC1 `EC PRIVATE KEY`. `from_openssh` finds its block the same way, so `read` and `from_openssh` never take different blocks of one file. The search keeps Go's offsets, which may fall below zero, and stops at the first header run that reaches the end of the text, which keeps it linear where a naive retry is quadratic.

A legacy encrypted block is decrypted as `x509.DecryptPEMBlock` decrypts it: DES, DES-EDE3 or AES-128/192/256 in CBC mode under OpenSSL's `EVP_BytesToKey` with MD5, the salt the first 8 bytes of the IV. A passphrase is used only where `Proc-Type` names `ENCRYPTED` and a `DEK-Info` names the cipher, as `x509.IsEncryptedPEMBlock` asks; otherwise it is refused as given for a key that is not encrypted. Padding that does not hold is a wrong passphrase, as Go has it; the check changes no outcome, since noise that passes it fails to parse, and no test sees it. A key that does not parse under a passphrase is a wrong passphrase too, which is broader than Go: Go says so only for an `asn1.StructuralError` and passes other parse errors through. An encrypted PKCS#8 block (`ENCRYPTED PRIVATE KEY`) is refused as Go refuses it.

The ASN.1 is read by RustCrypto's `pkcs1` (through `rsa`), `pkcs8` and `sec1`, borrowing from the decoded body without copies. Where they and Go differ in detail: the curve of a PKCS#8 EC key is the one its algorithm names, over any the inner SEC1 key names, as in Go; an Ed25519 key must have no algorithm parameters and may trail bytes after its 32-byte seed, as Go's `asn1.Unmarshal` leaves them; an RSA key's CRT values must follow from d, p and q, as Go's `Validate` checks them; and `pkcs8` refuses a version above 1, where Go reads any.

Two kinds Go reads are refused here: DSA, which the client does not sign with (`ssh-dss`), and an RSA key of more than two primes, which the core's `PrivateKey::rsa` cannot hold and an OpenSSH file cannot store. The maintainer chose on #45 to refuse the latter by name (`multi-prime RSA`) over adding a core constructor for it. X25519 and other PKCS#8 keys nobody signs with are refused by both. `KeyFile::read` takes any of the three formats as acwbroker's `parseKey` tells them apart: PuTTY's by its first line, then an OpenSSH block, then any other PEM.

The fixtures in `crates/justssh-keys/tests/pem/` were made by `ssh-keygen -m PEM`/`-m PKCS8` and `openssl` (`README.md` there); OpenSSL 3 writes DES only with its legacy provider, and the DSA key has 1024/160 parameters, the size Go reads, so that its refusal here is a difference the parity test sees. `go_reads_each_pem_key_as_justssh_keys_does` gives Go's `readkey` and `KeyFile::read` every fixture and finds the same verdict and public key, the three-prime key and the DSA key apart; sshd accepts the twelve keys it can be given (#45).

## What the proofs cover

The fixtures in `crates/justssh-keys/tests/keys/` were made by `ssh-keygen` 10.0, each with its own `.pub` line as the expected public key, and are kept byte for byte (`.gitattributes`). Against real peers: a Go client sees the same host key from a server built on a host key file Go's `MarshalPrivateKey` wrote, ed25519 and the `ssh-rsa`-only RSA alike; Go and `ssh-keygen -y` read every file written here; and sshd accepts all seven fixtures as client keys (`crates/justssh-tokio/tests/go.rs`, `sshd.rs`). That `ssh-keygen -y` check writes each key to a temp file first; a file in `%TEMP%` inherits the folder's ACEs, which the Windows OpenSSH `ssh-keygen` rejects as too open, so the test narrows it to the current user alone (`icacls /inheritance:r`), as `0o600` does on unix — without it the test fails only under PowerShell's system `ssh-keygen`, not under Git Bash's msys one or on Linux CI (#72).
